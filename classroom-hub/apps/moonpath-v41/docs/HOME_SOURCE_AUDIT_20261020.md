## 실제 수정과 검사

1. Windows 경로 구분자 때문에 내부 import를 외부 경로로 오인하던 빌더를 relative 경로 검사로 수정했다. 상위 디렉터리·절대경로 탈출 거부는 유지한다.
2. 문제팩 원본 바이트 및 src/dist LF 보존용 경로 한정 .gitattributes를 추가했다. Windows core.autocrlf로 발생한 원본 SHA 실패를 원본 변경 없이 해결했다. git에 저장된 문제팩·엔진 소스·빌드 결과 바이트에는 변경이 없다.
3. 이미 기록된 HOME B·캐릭터 방향 승인을 모두 미착수로 단정하던 낡은 테스트 두 개를 현재 승인 범위에 맞췄다. 실제 스프라이트 0·프레임 0·출시 차단은 계속 검사한다.
4. 승인 PNG 전체 바이트·치수·RGBA·후보 좌표·메뉴 및 출시 미승격 회귀검사 2개를 추가했다.
5. 로컬 실제 build 성공: HTML 335801바이트, 15모듈, 60문항. SHA256 `1b1ad7c94421600e2e3d11b247e37e3c634eb450dde237759548bbd21867acc3`, 기존 Git 빌드와 동일. Node 자동검사 530/530 PASS. 모의 IndexedDB 검사와 정적 검사가 포함되며 실제 브라우저 저장 증거는 아니다.
6. 내장 브라우저로 로컬 HTTP 시험 파일 접근을 시도했으나 `net::ERR_CONNECTION_TIMED_OUT`. HOME/시험 UI의 실제 클릭·저장·재로드 복원·file:// 테스트는 PASS가 아니다. Windows Chrome/Edge는 연결된 브라우저 목록에 없어 이번 검증에 사용하지 못했다.

## PNG 전송 경로

F5 프로젝트·서비스를 조회했고 배포 `cc997927-0c02-4789-90d3-6f107d352391` SUCCESS, `/health` HTTP 200을 확인했다. 이번에는 새 PNG 업로드·큐 접수·서비스 재배포를 하지 않았다. 기존 승인 파일이 이미 GitHub에 바이트 일치하므로 재전송이 필요하지 않다. 이번 health 확인만으로 PNG→Railway→GitHub 새 작업의 전체 전송 기능을 검증했다고 주장하지 않는다.

- HOME B 독립 배경·캐릭터·프레임·아이콘 원본의 런타임 연결, L0~L6 합성 및 실제 메뉴 클릭 영역.
