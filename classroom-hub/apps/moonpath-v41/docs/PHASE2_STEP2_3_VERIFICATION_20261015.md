## 2. 실제 구현 내용

| 하위 기능 | 실제 코드/작동 | 다음 단계 의무 또는 미검증 |
|---|---|---|
| `ANSWER_SUBMITTED` | 공식 `QUESTION_DRAWN`의 **교사용 발행 스냅샷**으로 2-1 채점기를 실행하여 원본 응답과 잠정 판정 하나의 이벤트로 기록 | UI를 통해 실제 학생 입력을 받아 처리하는 시험 미실행 |
| 잠정 판정 | 완전하고 명확한 자동판정 유형은 `correct`/`incorrect`; 서술형·불명확한 단답·부분 응답은 `needs_teacher` | 최종 교육적 정답·표현 인정은 교사 책임 |
| 타이머 연동 | 교사가 TIMER_STARTED를 수행한 문제만 답안 접수. 실행 중 남은 시간을 확정·일시정지 | 실제 시계 1초·중단·재개 브라우저 실증 미완료 |
| 만료 | 만료 자체는 **오답·회수·보상 변경 0**. 만료 뒤 답변 접수는 교사 승인 및 사유 필수 | 시간 경계에 대한 현장 조작 검증 미완료 |
| 교사 판정 | `ANSWER_JUDGED`: 교사 승인 후 `CORRECT` 또는 `INCORRECT` 확정, 교사 확인이 필요한 판정·자동 권고 변경에는 사유 필수 | 판정 후 재정정은 PHASE 2-7 의무, 이 단계에서는 임의 변경 불허 |
| 정답 분류 | 최종 `CORRECT` → `reviewEligibleIds` 추가, 반복 복습 정답 중복 추가 없음 | PHASE 2-6 전 별빛·열쇠 지급 0 |
| 오답 분류 | 최종 `INCORRECT` → `recoveryOnlyIds` 추가, 복습 후보에서 제거, `recovery.pending`에 원래 문제·모둠·지역·시도 ID 기록 | 가로채기·회수 우선권·실제 회수 실행 PHASE 2-5 |
| 무응답 | 시작 후 일시정지 또는 만료 시, 교사가 **미응답·오답 명시 확인 + 사유**를 기록해야 처리 | 무성의/포기 세부 운영 정책 후속 단계 검증 |
| 판정 우회 차단 | 실제 출제 시도에 `ATTEMPT_RESOLVED` 직접 사용하려면 **교사 확인 + 무효 사유** 필요. 답변 수신 뒤에는 판정 없이 종료 불가 | 정정은 2-7의 이력 보존 이벤트만 사용하도록 구현 필요 |
| 저장/복원 | 응답/잠정 판정, 교사 확정·복습/회수 분류, 이벤트 로그, 슬롯/체크포인트를 1회 IDB 거래에 기록하는 코드. 실패 시 메모리 갱신 금지 | FakeDatabase 모의 거래 검증만 PASS. 실제 브라우저 원자성은 미검증 |
| 교사/학생 정보 | 교사 API `TeacherEngineSession.submitAnswer/judgeAnswer` 제공, 학생 Projection에 정답·응답·교사 사유·감사 로그를 포함하지 않음 | 학생용 실제 읽기전용 두 창 통신/브라우저 검증은 PHASE 4~5 |

**중요:** 코드에서 `ANSWER_SUBMITTED`와 `ANSWER_JUDGED`는 *별도 이벤트*이지만, **각 이벤트 내 관련 상태·장부 변경은 각각 한 번의 거래**로 기록합니다. 두 이벤트가 한 거래로 동시에 저장된다고 주장하지 않습니다.
