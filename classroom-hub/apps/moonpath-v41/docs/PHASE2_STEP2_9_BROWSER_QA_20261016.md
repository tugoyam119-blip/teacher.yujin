# PHASE 2-9 · Windows Chrome/Edge 실기기 검증 체크리스트 (미실행)

**상태:** 아직 현장 실행 증거가 없습니다. 표시된 단계는 앞으로 직접 실행하고 기록할 항목입니다. 이 목록을 만들었다고 PASS로 표기하지 않습니다.

## 시험 전

- 시험 대상: `dist/phase2-9-one-region-smoke.html` (**교사 전용 비운영 파일**). 이 파일은 60문항 정답·해설을 내장하므로 학생에게 공유하지 않습니다.
- 브라우저: Windows Chrome/Edge의 **버전 번호**, OS, 날짜/시각, 화면 해상도, 파일 경로 기록.
- 실제 운영 저장소와 절대 공유하지 않는 시험 전용 데이터베이스 이름: `moonpath-v411-phase29-smoke-db-v1`.
- 가능하면 별도 **새 브라우저 프로필**을 사용합니다. 기존 클래스룸과 운영 게임은 수정·초기화·삭제하지 않습니다.

## 실기기 1지역 플레이

1. 브라우저에서 시험 HTML을 직접 `file://`로 열어 정상 실행되는지 검사합니다. IndexedDB 오류/권한 거부가 나오면 즉시 BLOCKED 또는 FAIL 원인을 기록합니다.
2. 슬롯 Ⅰ·모둠 2개 → **새 시험**. 달빛 이끼길 진입/기본문제 수=2인지 확인합니다.
3. 모둠 1 문제 준비 → 교사 타이머 시작 → 답변 제출 → 교사 정답 확정. 별빛+1/모둠 공헌+1 확인.
4. 모둠 2 문제 준비 → 타이머 시작 → 답변 또는 명시적 미응답 → 교사 오답 판정 → 가로채기 모둠 1로 실행해 정답 확정. 원모둠 회수 기록은 유지되어야 합니다.
5. **지역 완료 확정**: 지역 열쇠+1, 완료 자체 별빛+0, 지역 기본 2문제 중 정답1/오답1, 미회수1 표시. 중복 완료 불가.
6. **다음 지역 진입** 후 원모둠 회수 호출→답안 제출→교사 정답. 별빛 총3/열쇠1/미회수0이 되는지 확인하고 원답안 변경 없음 검사.
7. 같은 유형의 시험을 모둠4·모둠8로 독립 슬롯/프로필에서 실시해 기본 문제 수에 따른 지역 완료를 확인합니다.

## 실 저장·재시작·강제 종료

8. 새로운 슬롯 또는 별도 프로필로 게임 도중 타이머 RUNNING에서 브라우저를 **완전히 강제 종료**한 뒤 동일 프로필·동일 `file://` 경로로 열어 `이어하기`를 누릅니다. 저장된 타이머는 자동 실행되면 안 되며 교사가 수동 재개합니다.
9. 답안 판정·보상 확정 직후 강제 종료/재개에서도 원문제·별빛·열쇠·대표 명단 버전·이벤트 순번이 동일한지 비교합니다.
10. 개발자 도구를 이용한 저장 거부·거래 abort·공간 제한 등 재현 가능한 안전한 별도 시험 조건을 사용해 저장 실패를 유도합니다. 실패 시 성공 안내/보상 확정 표시가 없어야 하며, 이전 정상 체크포인트를 보존해야 합니다. 검사 방법/로그와 안전 복귀 절차를 기록합니다.
11. JSON 백업 파일을 내보내고 파일 SHA와 크기 확인; 원본 슬롯을 덮어쓰지 않는 **빈 슬롯/새 프로필**에 해당 슬롯 번호 그대로 복원합니다. 임의 슬롯 번호 변경은 허용되지 않습니다.
12. 교사 창 중복 접속 충돌/업데이트, 학생 공개용 창 전송은 **현 단계에서 구현하지 않았으므로 V14 PASS 금지**. 실제 확장 모드 구현 후 별도 테스트합니다.

## 오프라인 및 호환성

13. 외부 네트워크를 끊은 상태에서 파일을 새로 열고 1지역을 재진행합니다. 외부 CDN/폰트/서비스를 호출하지 않아야 합니다.
14. Chrome·Edge를 각각 테스트합니다. `file://`의 IndexedDB 쓰기와 BroadcastChannel은 브라우저 정책/경로에 따라 달라질 수 있으므로 한 브라우저 성공을 다른 환경의 PASS로 대체하지 않습니다.
15. 화면 1920×1080, 1600×900, 1366×768, 430×900에서 잘림·포커스·텍스트 레이아웃을 기록합니다. 시험 화면의 contain 성공은 최종 신규 아트/UI V20 PASS가 아닙니다.

## 기록 및 판정

각 테스트에서 **테스트 ID / 날짜 / OS·브라우저 버전 / file:// 또는 localhost / 빌드·커밋 SHA / 사전 데이터 / 실행 순서 / 예상 결과 / 실제 관측 / 로그·스크린샷 / 실패 조치**를 남깁니다.

- `PASS`: 해당 실기기·조건에서 실제 측정한 증거가 있는 개별 테스트만.
- `FAIL`: 실제 기능 실행 후 관측 결과가 요구와 다름.
- `BLOCKED`: 시험 환경 제한으로 기능 자체를 실행하지 못함.
- `NOT_RUN`: 시험을 하지 않음.

**모든 공식 V01~V22 게이트가 실제 증거로 통과하고 사용자 최종 승인하기 전에는 운영 `main` 병합·Railway 배포하지 않습니다.**
