### 상태·동작 계약

1. 모둠 ID는 `TEAM_01`…`TEAM_08`, 설정에서 2~8개; 학생 ID는 해당 원정 전체에서 중복할 수 없음. 동일 이름은 허용하되 **고유 ID로 구분**.
2. 출석 상태: `PRESENT`(대표 후보), `ABSENT`, `LATE`, `LEFT_EARLY`, `INACTIVE`(대표 제외). 처음 명단을 가져오지 않은 모둠은 교사 주도형으로 대표 ID `null`을 저장하며 특정 학생을 만들어내지 않음.
3. 학생 이동은 기존 학생 ID와 출석 상태를 보존하되, 출발·도착 두 모둠의 명단 버전을 각각 +1. 원래 모둠 구성과 대표를 문제 시도 내 변경 불가능한 이력 사본으로 저장.
4. 같은 모둠의 대표는 **명단의 순서를 유지하며 출석자만 건너뛰는 순환**. 모둠 간 턴도 다음 모둠을 자동 추천하고, 수동 선택은 별도 기록. **해결자 ID는 대표 ID로 자동 추정하지 않음**.
5. 교사 변경 명령/출제 이벤트, 시도 스냅샷, 감사 이력 및 체크포인트는 PHASE 1 저장 계층을 통해 단일 거래에 반영하도록 구현. **모의 IndexedDB에서만 원자적 실패 롤백을 확인**.
6. 학생 공개용 `publicProjection()`에 학생 실명·개인 고유 ID·출석·명단·원답안·판정 감사·내부 명단 버전을 내보내지 않음.
