## 2. 실제 구현 방식

### 2.1 정정 명령은 원답안·원판정을 덮어쓰지 않음
- 교사 전용 `JUDGEMENT_CORRECTED` 이벤트: `scope=ANSWER|INTERCEPTION|RECOVERY`, 대상 ID, 새 판정, 3~2000자 근거, 교사 확인을 요구.
- `s.corrections.records[]`에 원판정→정정판정, 이벤트 ID·시각·원시도 ID·문항 ID·근거를 **추가**. 이전 원판정, 답변, 원모둠·대표·명단 버전, 실제 해결 모둠, 과거 이벤트 로그는 그대로 유지.
- 이미 판정된 미션을 정정해도 역사적 미션 시도 기록 자체는 삭제하지 않음. 현재 자격과 **진행 당시 적법한 자격**을 분리해 과거 가로채기를 위조·삭제하지 않음.
- 사건 중복 클릭은 기존 이벤트 멱등 규칙을 따르고, 같은 이벤트 ID/다른 정정 내용은 `EVENT_ID_CONFLICT`로 거절.
- 활성 원문제나 미션이 남아 있을 때 정정을 차단, 저장 원자성 위반 회피.

### 2.2 파생 가로채기·회수의 실효성과 보상 재계산
- 원판정을 `INCORRECT→CORRECT`: 해당 원문제의 복습 자격을 되돌리고 미회수 대기를 `INVALIDATED`로 표시. 기존 가로채기·회수 *역사*는 보존하되 해당 출처의 별빛 지급과 공헌도 실효성을 다시 계산.
- 원판정을 `CORRECT→INCORRECT`: 기존 최초 정답 별빛·공헌도를 반납하고, 실제 당시 ID/지역/모둠/명단 버전을 지키며 회수 대기 항목을 생성. 기존 정답·원시도 이력은 삭제하지 않음.
- 기존 정답이 잘못됐을 때 과거 유효한 가로채기 정답으로 **실효 최초 보상 수령 모둠을 변경**할 수 있음. 원문제 정정 전·후 모둠 공헌도 합계가 불변인 경우와 감소하는 경우를 분리하여 검사.
- 기존 성공한 회수 판정을 오답으로 정정하면 원회수 실행 기록을 보존한 채 다시 대기 상태로 이동, 이후 타모둠 재도전으로 유효한 해결 모둠이 바뀌어도 별빛 추가 채굴 없이 재귀속.
- 정정 뒤 전 상태를 토대로 `FIRST_CORRECT:<questionId>` 및 `RECOVERY_CORRECT:<questionId>`의 유효 권리를 재평가. 출제되지 않은 정답/마법 지급을 만들어내지 않음.

### 2.3 보상은 수정이 아닌 보정 장부 행으로 정산
- 기존 `STAR_EARN`/마법 소비 장부는 **불변으로 보존**, 정정 이벤트에 매인 `STAR_ADJUST` 양수·음수 행을 추가해 유효 수령 모둠/공헌도 조정.
- 정정 전 별빛을 이미 썼다면 `rewards.starlight = max(0, 유효 별빛 적립 - 기록된 소비)`, `settlementDue = max(0, 소비 - 적립)`, `settlementRequired = settlementDue > 0`.
- `settlementRequired=true`이면 마법 5종과 구형 `TIME_SAND_USED` 소비를 차단; 음수 잔액을 그대로 노출하지 않음.
- 새 정답 또는 교사 재정정으로 부족액이 충당되면 정산 필요 상태를 다시 해제. **과거 실제 마법 사용, 시간 연장, 소비 이벤트는 삭제하거나 소급 환불하지 않음**.
- 정정된 상태에서 이후 회수 재도전 성공 시에도 새 이벤트를 근거로 한 정산 보정만 기록하고 이미 적립했던 청구를 중복 지급하지 않음.
