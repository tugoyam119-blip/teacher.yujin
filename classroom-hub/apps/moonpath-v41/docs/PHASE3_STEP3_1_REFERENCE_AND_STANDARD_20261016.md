## 1. 이 단계에서 무엇을 완료하는가

1. 과거 사용자 승인·선호 픽셀아트와 구형 시안(승인 불명)을 **서로 다른 근거 수준**으로 분류하고 실제 PNG 파일의 크기/모드/바이트/SHA-256을 기록했습니다.
2. 사용자 지정 시각 정체성(보랏빛 장발 치비 마도사, 어두운 남색·라벤더, 달빛/별빛과 금빛 등불, 부유섬/폭포/성역, 실제 Y자 갈림길)을 새 제작의 비교 기준으로 정리했습니다.
3. 960×540 무대, L0~L6, 64×64 캐릭터(필요 시 128), 24/32px 아이콘, 중앙 문제 팝업 820×440 최대 크기, 전 화면 `contain` 규칙을 데이터 계약으로 저장했습니다.
4. 16단계 상태 추적표·새 자산 레지스트리·실파일 해시 검사 스크립트와 정적 테스트를 마련했습니다.

**아직 수행하지 않은 작업:** 사용자 신규 시안 승인, 최종 팔레트 픽셀 미세 계측·합성 승인, 실제 새 PNG 원본 업로드/표시, 화면/저장/온라인·오프라인 실증. 완성 화면이라고 주장할 수 없습니다.

| 방식 | 차이 | 장점 | 제약 |

## 7. 신규 에셋 등록·승인 게이트

상태 축을 독립 보관합니다. `CANDIDATE`(새 원본 제작) → `원본 파일 SHA-256` → `GitHub 전체 바이트 일치` → `실제 브라우저 이미지 표시` → `사용자 디자인 승인` → `실제 클릭/기능 QA` 순서 중 어디까지 실제로 끝났는지 기록하고 임의 승격을 금지합니다. 화면별 승인도 자산 단위 승인과 별도로 기록합니다.

필수 항목: assetId, 신규 원본 파일, 가로/세로/알파, 피벗·레이어, sourceReferenceIds, SHA256, Git blob SHA, 브라우저 스크린샷, 사용자 승인 근거, QA 결과, 온라인/오프라인 양쪽 실빌드 사용 여부.

**이번 3-1에서는 기존 아트 원본을 GitHub에 업로드하지 않습니다.** 새 PNG는 0개이고 새 PNG의 업로드/브라우저 표시/V18·V19·V20 전체 PASS 또한 0개입니다.
