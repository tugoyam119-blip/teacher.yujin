## 1. 실제 구현한 기능

| 구분 | 구현 사실 | 제한/추가 작업 |
|---|---|---|
| 전체 60문항 | 2-1 `createQuestionEngine`이 검증한 원본 60개 고유 ID 사용, 지역별 문항 고정하지 않음 | 실제 수업 난도·유형 분포 타당성 평가는 별도 |
| 미출제 우선 | `issuedIds`에 없는 문항만 `NEW`, 60개 소진 이전 복습 무조건 차단 | 모든 문항 사용 뒤 학습 출제 정책은 결정31 유지 |
| 난도·유형 균형 | 문항팩의 전역 유형·난도 비율에 대한 차이값을 최소화하고 균형이 같은 후보를 난수로 선택. `random()` 주입으로 재현 가능 | 균형을 보장하는 방식은 원본 분포에 맞춘 후보 선정이며 임의 난도 순서를 만들지 않음 |
| 복습 | 신규 60개 소진 후에만 `reviewEligibleIds`의 해결된 문항으로 `REVIEW`. 같은 지역 재출제는 대안이 있을 때 회피 | 정답 판정 후 복습 자격 등록은 2-3에서 실제 연결 예정 |
| 오답 회수 분리 | `recoveryOnlyIds`는 일반 `NEW`/`REVIEW`에서 제외; `listRecoveryCandidates`는 읽기 전용 목록 | 회수 판정·원래 모둠 우선·사용자가 호출/보류·회수 보상 등은 2-5/2-6 |
| 회수 자연 등장 안전 조건 | 확인된 `world.regionEntryOrder`의 현재 지역 방문 순서가 원오답 지역 뒤일 때만 조회, 증거 없으면 보수적으로 보류 | 실제 `regionEntryOrder` 작성/관리 및 추가 탐험 복귀 연동은 2-8에서 구현해야 함. 지금은 시험 데이터로만 검사 |
| 저장 동시성 | `TeacherEngineSession.drawQuestion()` → `QUESTION_DRAWN` → 원본/발행 스냅샷 + PREPARED 시도 + `issuedIds` + 출제 이벤트 + 두 체크포인트를 같은 모의 IndexedDB 거래로 확정 | Chrome·Edge의 네이티브 IndexedDB 환경 실증 불가 상태 유지 |
| 중복 출제 | 동일 이벤트 ID의 중복 클릭은 최초 문항/시도 반환, 다른 내용 같은 ID는 충돌. 같은 문제 진행 중 새 출제 차단 | 재접속 뒤 저장소 실제 동작은 브라우저 시험 필요 |
| 보상 | `NEW`/`REVIEW` 모드를 기록하지만 이 단계에서는 별빛·열쇠·공헌도 **지급하지 않음** | 2-6의 보상 장부와 2-7 정정 재계산 후 통합 검증 |

## 5. 차기 2-3 인수인계

- 실제 `QUESTION_DRAWN`으로 확정한 `attempt.questionSnapshot`을 2-1 `gradeQuestionResponse()`에 연결하고, 타이머 만료는 **자동 오답 처리하지 않는다**.
- 교사 최종 판정(정답/오답/검토 필요)을 이벤트로 확정하고, **정답은 복습 후보 / 오답은 회수 전용**으로 안전하게 이동하되 보상은 2-6 전까지 지급하지 않는다.
- 저장 실패 시 판정·분류·시도 완료 모두 롤백; 다중 클릭/재시작 후 로그 멱등 보장.
- 원본 답안·교사 루브릭·감사 내역은 학생 공개용으로 전송하지 않는다.
- 2-5에서는 실제 방문 이력 및 원래 오답 모둠의 회수 우선권/보류/강제 호출을 연결한다.
