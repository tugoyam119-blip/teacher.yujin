## 2. 저장 불변식

- 기존 `moonpath-dev` 운영 파일, `localStorage` 키, 저장 데이터는 읽거나 쓰지 않음. DB 이름은 `moonpath-v411-engine-db`.
- `commit()`은 `slots`/`events`/`checkpoints`/`leases`를 **한 개의 IndexedDB readwrite 트랜잭션**에서 작성하며, `transaction.oncomplete`가 발생했을 때만 성공으로 반환함.
- 실패/QuotaExceeded/lease 경합/중복 revision은 예외를 전달하고 진행 메모리를 성공 상태로 교체하지 않음.
- `eventId` 재실행은 기존 이벤트 확인 뒤 추가 저장·보상 없이 반환함.
- 최신/직전 체크포인트 2세대 보존. 저장 영역이 손상되면 유효 체크포인트를 자동으로 덮어쓰지 않음. 교사 명시적 복구 시 원래 손상 데이터는 `quarantine` 저장소에 분리 보존함.
- 교사용 writer lease 30초, 약 10초 heartbeat, 사용자 명령 직전 소유권 재확인. 다른 교사 창으로 소유권을 넘긴 후 기존 창은 쓰기 실패.
- 재접속/복원 시 타이머는 자동 재개하지 않음. **정지 직전 잔여시간은 마지막 저장 체크포인트 기준**이며, 종료된 브라우저 동안의 활성 시간은 임의 계산하지 않음. PC 시계 급변/장기간 미정확 경과시간 검증은 미실시.
- 백업 파일 SHA-256은 파일 무결성 검사일 뿐 보안 서명은 아님. 오프라인 사용자가 파일 자체를 분석하지 못하게 하는 강력한 보안 방식은 아님.
- 학생 공개 상태에는 정답·해설·PIN·관리자 감사·미발견 단서가 없음. 하지만 실물 학생 창에서의 통신 구현은 아직 없음.

## 3. 실행한 검사와 구분

- Node.js v22.16.0, `node --test`: 신규 PHASE 1 테스트 30건 **PASS** (순수 reducer + 가상 IDB 거래 모형). 가상 DB는 `tests/support-fake-idb.mjs`가 제공하는 인메모리 시험 도구이며 실제 브라우저 IndexedDB 구현은 아님.
- 기존 PHASE 0 문제은행 정적 검증 코드 `tests/phase0.test.mjs`는 유지함. 30건은 PHASE 1 신규 테스트 수치이며 이전 정적 검증 건수를 더한 수치라고 주장하지 않음.
- 실제 Windows Chrome/Edge, `file://`, 두 창 BroadcastChannel, PDF/CSV/JSON 파일 UI, 오프라인 단일 HTML 빌더, 풀게임 플레이는 **NOT_RUN**.
- 원래 PHASE 0 브라우저 사전 프로브는 관리자 정책 때문에 **BLOCKED**. 이는 기능 자체 FAIL을 뜻하지 않음.
- V09(타이머), V11(IndexedDB), V12(3슬롯/JSON), V14(단독 쓰기)에 대해 기초 모듈이 작성됐어도 통합 게이트 PASS는 아님.

## 4. PHASE 1 완료를 선언하기 전에 필요한 것

1. 실제 온라인/`file://` Chrome/Edge에서 트랜잭션 중단·용량 초과·재시작/강제 종료를 반복 검사.
2. 60초 타이머 만료 1초 전후 교사 조작/탭 일시정지/브라우저 재시작의 실제 시간 검증.
3. 3슬롯·손상/교사 복구·JSON 파일 내보내기·복원 실제 브라우저 시험.
4. 학생 공개창 수신·다중창 쓰기 충돌·동기화 장애 처리는 PHASE 4~5 게이트를 따로 통과.
5. 사용자 승인 전 `main` 병합, PR 자동 병합, Railway 배포, 기존 클래스룸 연결 금지.
