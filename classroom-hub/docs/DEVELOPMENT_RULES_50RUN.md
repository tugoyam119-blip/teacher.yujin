# 유진T 클래스룸 개발·패치 규칙

## 핵심 원칙
- 기존 프로그램의 좋은 기능은 유지하고 재사용 가능한 공통 기능으로 승격한다.
- 불편했던 구현은 해당 프로그램만 고치는 데서 끝내지 않고 deprecated로 기록하여 신규 프로그램에 복제하지 않는다.
- 학생 화면에는 패치 설명이나 시스템 개발 문구를 노출하지 않는다.

## 필수 검증 절차
1. 현재 정식 프로그램 ID·정식 버전 확인
2. 교사 관점 50회 운영검증
3. 공통 불편과 프로그램 고유 불편 분리
4. 수정 전 백업
5. 개발버전에 패치
6. 동일한 50회 회귀검사
7. 핵심 기능 전부 통과 후 정식버전 승격

## 50회 시나리오에 반드시 포함
수업 전 준비, 첫 반, 다음 반, 모바일, 재접속, 새로고침, 잘못된 입력, 잘못된 파일, 이전 기록 존재, 서버 닫힘/열림, 제출, 채점, 초기화, 복구, 버전 확인.

## 공통 UI 규칙
- 열리는 패널/모달/드로어는 사용자가 직접 닫을 수 있어야 한다. 모바일 닫기 버튼은 필수다.
- 화면에 보이는 주요 버튼은 실제 기능이 연결되어 있어야 한다.
- 전체 초기화는 테스트 기록/특정 반/전체 기록으로 구분하고 큰 초기화 전 백업을 남긴다.
- 공용기기 학생 데이터는 학생/세션 단위로 분리하거나 수업 종료 시 안전 초기화할 수 있어야 한다.
