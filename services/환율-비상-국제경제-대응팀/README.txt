학생 접근 보강 (검토용 변경)
- 학번·이름만으로는 입장할 수 없습니다. 교사 관리실에서 명단 학생을 선택하고
  「코드 발급·재발급」을 눌러 개인 입장코드를 발급한 뒤 그 학생에게만 전달합니다.
  코드는 발급 응답에만 표시하며, 재발급하면 기존 코드와 해당 학생의 세션이 취소됩니다.
- 개인 코드는 암호학적 난수 128비트이고 DATA_DIR/student-access.json에 SHA-256
  해시로만 저장합니다. 이 파일도 기존 exchange-crisis.json과 함께 영구 볼륨에 보관하세요.
  실제 코드 발급이나 학생에게 전달하는 작업은 이 패치에 포함되어 있지 않습니다.
- 로그인 쿠키는 HttpOnly/SameSite=Strict이며 8시간 유효합니다. 운영 HTTPS에서는
  NODE_ENV=production을 설정하세요(Secure 쿠키). 프록시의 HTTPS 표시도 인식합니다.
  서버 재시작 시 세션은 만료되지만 개인 코드와 기존 답안은 유지됩니다. 다시 입장하세요.
- 이 JSON 파일 기반 서버는 단일 프로세스/단일 인스턴스로 운영해야 합니다.
  여러 인스턴스를 쓰려면 공유 세션 저장소와 트랜잭션 저장소가 먼저 필요합니다.
- TEACHER_PIN이 없으면 교사 인증이 차단됩니다. 이전 기본값 000000은 제거했습니다.
  강력하고 고유한 교사 인증번호를 설정하고 비공개로 보관하세요.
- 학생은 본인의 응시 기록과 도움 요청만 조회할 수 있고, 채점점수·피드백·이력은
  학생 응답에서 제외합니다. 명단과 기존 응시 기록의 이름/반이 달라지면 교사 확인
  전까지 학생 접근을 차단하며 기존 기록은 덮어쓰지 않습니다.
- 시작 전·일시정지·종료·시간 만료·최종 제출 후에는 서버에서도 답안 수정을 거절합니다.
  시간 만료 시 마지막으로 저장된 답안은 그대로 보관되며 자동 제출로 바꾸지 않습니다.
  교사는 유효한 진행 시간 안에서 「재작성 허용」을 사용할 수 있습니다.
  시간이 끝났다면 먼저 추가시간을 승인해야 합니다. 학생의 자기 재개는 차단합니다.
- 추가시간은 기본 마감시간을 줄이지 않습니다. 일시정지 중에는 승인된 추가시간도
  멈추고 재개 시 남은 시간이 보존됩니다. 기존 시간감점 계산식은 유지합니다.
- 기존 답안·채점 기록·이관 API와 데이터 구조는 유지합니다. 이 변경은 배포하거나
  실제 학생 데이터로 시험하지 않았습니다. 배포 전에 검토와 별도 승인이 필요합니다.
- 교사 인증 실패는 서버가 확인한 연결 주소별로 1분에 10회까지 허용하며 이후
  잠시 차단합니다. 프록시/공용 네트워크 사용자는 한 제한을 공유할 수 있습니다.
  전달받은 IP 헤더는 신뢰하지 않습니다. 제한은 단일 서버 메모리 기준이며 재시작 시
  초기화됩니다. 짧은 6자리 번호 대신 충분히 긴 무작위 TEACHER_PIN을 권장합니다.
  이 패치는 운영 환경변수를 설정하거나 기존 비밀값을 변경하지 않습니다.
