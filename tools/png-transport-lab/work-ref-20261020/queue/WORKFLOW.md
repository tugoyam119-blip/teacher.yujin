# F5 제작용 표준 실행 절차 + 영구 작업 큐 v1
2026-10-20. 적용 범위: png-f5-receiver / test 환경. 운영 main 병합 금지.

## 제작에서 사용하는 절차
1. 사용자가 요청한 이미지만 생성·수정한다. 승인 이미지는 원본을 재생성하거나 덮어쓰지 않는다.
2. 생성 도구가 반환한 실제 원본 경로 또는 지원되는 파일 참조를 사용한다. 참조가 없는 경우 발급 가능한 척하지 않는다.
3. 지원되는 파일 접근 기능으로 원본을 읽어 전체 크기와 SHA-256을 계산한다.
4. 원본 다운로드 참조, bytes, sha256, test/ 브랜치, tools/png-transport-lab/ 아래 새 PNG 경로로 작업 명세를 구성한다.
5. ChatGPT 연결에서 기존 UPLOAD_TOKEN 값을 읽을 수 없으므로, 현재 검증된 경로는 F5_QUEUE_JOB 환경변수로 명세를 서버에 전달하고 재배포하는 방식이다. 일괄 처리 시 배열을 사용한다. 토큰과 서명 URL을 GitHub·채팅·로그에 기록하지 않는다.
6. 서버가 영구 큐에 등록한 후 원본 다운로드 → 크기·SHA·PNG 검증 → commit=false 수신 검증 → 원격 동일 파일 확인 → 필요한 경우만 커밋 → GitHub 콘텐츠 API 전체 다운로드 검증을 실행한다.
7. 작업 succeeded와 원격 해시/크기를 확인하고, Work에서도 전체 파일을 독립 다운로드해 원본과 비교한다.
8. F5_QUEUE_JOB을 빈 문자열로 지우고 재배포한다. 이때 SQLite 기록과 검증된 원본 캐시는 유지된다.
9. 기존 테스트 PR을 갱신하거나 별도 초안 PR을 생성하고 링크·해시·한계를 보고한다. main 병합은 하지 않는다.

## 작업 API
모든 /api/jobs 요청에 기존 Authorization Bearer UPLOAD_TOKEN이 필요하다.
- POST /api/jobs: {download_url,bytes,sha256,branch,path}. 신규 202 / 동일 작업 200.
- GET /api/jobs: 최근 100개 작업.
- GET /api/jobs/{id}: 단일 작업 상태.
현재 ChatGPT에 직접 호출용 인증 연결이 설치된 것은 아니다. 이 세션은 위 5번 경로를 사용한다.

## 영구 상태와 중복 방지
500MB Railway 볼륨 /data; SQLite WAL + synchronous FULL.
키는 branch + path + SHA-256. 같은 요청을 반복해도 작업은 하나만 생성된다.
검증된 원본은 /data/f5-cache/{sha}.png에 보관한다. 재시작·일시 오류 시 URL 재다운로드를 줄인다.
다운로드 완료 후 DB의 원본 URL을 제거한다. 상태 API와 로그에는 URL·토큰을 내보내지 않는다.
queued → downloading → verified → committing → succeeded.
일시 오류는 retry_wait에서 지수 지연으로 최대 3회 시도한다.
만료·권한 오류 소스는 needs_source로 전환한다. 새로 발급한 URL로 같은 작업을 다시 접수할 수 있다.
failed/needs_source 재접수는 시도 횟수를 초기화한다. 같은 URL의 자동 갱신 기능은 없다.
재시작 때 downloading/verified/committing 작업을 queued로 되돌린다.
커밋 직전 원격 동일 SHA를 확인하므로, GitHub 커밋 후 DB 기록 전에 중단된 작업은 동일 파일 커밋을 건너뛸 수 있다.

## 검증 중 발견·수정
초기 버전은 커밋 직후 raw.githubusercontent.com 다운로드에서 404를 받았다.
GitHub에는 실제 파일이 존재했으며, 초기 재시도 중 추가 커밋이 발생했다.
최종 코드는 인증된 GitHub 콘텐츠 API raw 응답으로 전체 파일을 내려받아 확인한다.
수정 전 추가 커밋은 시험 이력으로 남겨 두었다. 운영 main/승인 이미지에는 영향이 없다.

## 운영 한계
- 단일 서비스·단일 실행자 구조이며 다중 복제본/여러 서비스의 동시 쓰기는 검증하지 않았다.
- API는 배포 없이 접수할 수 있지만, 현재 연결된 ChatGPT는 토큰값을 받지 못하므로 명세 전달에 재배포가 필요하다.
- 새 ImageGen 생성 완료 이벤트를 구독하는 상시 트리거는 없다. ChatGPT가 작업을 이어가는 동안 표준 절차로 실행한다.
- 이번 검증은 기존 20MB 원본을 사용했다. 새 게임 이미지를 임의로 제작하거나 승인 이미지를 바꾸지 않았다.
- 중단 복구 시험은 커밋 완료 직후의 미완료 DB 상태를 의도적으로 만든 뒤 실제 재배포한 시험이다. 실제 전원 장애 시험은 아니다.
- 원본 캐시 자동 삭제·볼륨 사용량 경보·자동 PR 생성은 큐 자체에 포함되지 않는다. PR 처리는 위 표준 절차가 담당한다.
- 500MB 볼륨 용량 내에서 사용한다. 오래된 캐시는 검증 완료 후 별도 정리 절차가 필요하다.
