# PNG 원본 GitHub 업로드 제작 기준 v1.1 (검증 기반)

## 목표
ChatGPT 제작 이미지(PNG)의 원본 바이트를 손상 없이 GitHub에 등록한 후 게임 소스에 반영한다.

## 현재 검증된 경로
1. 로컬 PNG 파일 전체 바이트를 확보한다.
2. 파일의 SHA-256 및 Git Blob SHA-1을 계산한다.
3. Base64로 인코딩한 문자열을 인증된 GitHub `create_blob(content, encoding="base64")`에 전달한다.
4. 원본을 교체하지 않는 별도 브랜치에서 `create_tree` → `create_commit` → `create_branch`로 경로를 등록한다.
5. `fetch_file(path, ref, encoding="base64")`로 재조회해 전체 바이트와 SHA-256을 비교한다.
6. 원본 일치, 이미지 형식/디코딩, 게임 화면 QA가 끝나기 전에는 main 병합 또는 운영 배포를 하지 않는다.

## 성공과 미검증 구분
- 확인: 이전 69바이트 PNG 왕복 전송 완료. 2026-10-20 크기 97,453바이트 PNG `create_blob` 접수 완료 (SHA `13b51560c8ef35f779d4069b2b6ca88574fdd4a1`).
- 재조회/전체 무결성: 해당 파일을 브랜치에 등록하고 `fetch_file`로 확인하여 기록한다.
- 미검증: 실제 게임 승인 원본 PNG, 500KB 이상 전송 한계, 모델/실행환경 간 파일 바이트의 무인 전달, 새 이미지의 게임 UI 실제 적용.

## 자동화 정책
- 우선순위 A1+B2: Base64 GitHub Blob + 재사용 가능한 공통 업로드 워크플로.
- 입력: 파일 경로/대상 저장소/대상 경로/작업 브랜치.
- 산출: 원본 해시 기록, Blob/Tree/Commit SHA, 별도 브랜치, PR, 왕복 검증 기록.
- 주의: GitHub `create_blob`의 인자는 바이너리 파일 경로가 아니라 문자열이다. 로컬 바이트를 GitHub 연결 호출 인자로 자동 주입하는 브리지가 없는 경우 수동 전달 단계를 성공으로 표시하지 않는다.
- Base64가 큰 경우에는 사이즈 상한을 측정한 후 서버 직접 업로드(B3/A5)나 설치된 커스텀 파일 바이트 전달 도구를 검토한다. 조각 분할만으로 GitHub `create_blob` 업로드는 할 수 없다. 서버 재조립 과정이 필요하다.
- 비밀 토큰을 문서, PR, 클라이언트 코드에 넣지 않는다. 서버 측 비밀 변수와 최소 권한을 사용한다.
- sha 불일치 시 중단, main 보호, 기존 승인 이미지·좌표·레이어 변경 금지.

## 추가 성공 판정 기준
- 실제 승인된 게임 PNG를 대상으로 GitHub에 커밋, 재조회 후 SHA-256 100% 일치.
- 사용자 업로드 반복 없이 ChatGPT에서 파일 생성→바이트 확보→GitHub 업로드까지 이어지는 경로 실증.
- 최소 3회 연속 성공, 실패 복구·중복 업로드·큰 파일·권한 오류 테스트.
- 구현과 게임 화면 QA 성공 후 본 문서의 검증 상태만 변경한다.

## 2026-10-20 추가 실측 — 대용량 시험 (v1.2 반영 메모)
- 600×600 PNG **1,080,748 bytes**, Base64 **1,441,000 chars**: create_blob 반환 SHA `4bbeca9e9b2729b7408425d32f05cf95f620c2d7`. Tree/Commit/branch에 등록 성공. fetch_file(encoding=base64)는 SHA가 일치하나 content가 빈 문자열로 반환됨(2회). 따라서 왕복 완전검증 **실패/미충족**.
- 1024×1024 PNG **3,147,060 bytes**, Base64 **4,196,080 chars**: 연결 호출에서 `h2 protocol error: error reading a body from connection`; GitHub Blob 생성 성공 확인 불가. 재시도 또는 다른 전송 경로 필요.
- 1MB 정도의 승인 PNG 자체를 로컬 환경에서 읽어 GitHub create_blob 인자로 자동 공급하는 브리지는 구축되지 않음. 합성된 시험 PNG를 connector 실행 환경 안에서 생성·업로드한 경우만 확인.
- 성공 판정: 실제 승인 게임 PNG, 재조회 원본 SHA-256 완전 일치, 이미지 생성부터 업로드/PR/게임 적용 자동화 및 최소 3회 연속 검증 통과 전까지 **기술 검증 단계**.
- 대용량 이미지에 Base64 전체를 연결 인자 한 번에 싣는 방식은 한계를 확인했으므로, 파일 바이트를 서버로 직접 보내는 인증된 스트리밍 업로드 또는 별도 file-native connector 개발을 우선 검토한다.
